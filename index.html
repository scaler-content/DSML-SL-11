01What Are We Actually Optimizing For?

Every classifier — Logistic Regression, kNN, Decision Trees — finds some boundary that separates classes. SVM asks a sharper question.

Out of every boundary that correctly separates the training data, which one will generalize best to a text message it has never seen? Picture two clusters of points: one boundary drawn snugly against a handful of points on one side, another drawn with generous, even breathing room on both sides. The second is far more likely to handle a slightly different, unseen point reliably — and that intuition is the entire premise SVM is built on.

What does "generalization" mean, in the context of SVM?
  • How far the hyperplane is from the training datapoints
  • How accurately the model predicts outcomes for unseen (test) data
  • How accurately the model classifies the training datapoints it was trained on
Why: Generalization is about performance on data the model has never seen, not the training set. Distance to training points is related — it's exactly the mechanism SVM uses to improve generalization — but it isn't the definition. Training accuracy can be perfect while generalization is poor.

02The Hyperplane and Its Margin

A hyperplane is SVM's decision boundary: wᵀx + b = 0. Points on one side are predicted positive, points on the other, negative.

SVM doesn't stop at one boundary line. It considers two more hyperplanes, parallel to it — one just touching the nearest positive points, one just touching the nearest negative points:

π₊ : wᵀx + b = c₊     π₋ : wᵀx + b = c₋

The margin is the distance between π₊ and π₋:

margin = (c₊ − c₋) / ‖w‖
Interactive · The Margin & Support Vectors

Only the ringed points — the support vectors — sit exactly on π₊ or π₋. Every other point could vanish, the model retrained, and the boundary wouldn't move at all.

Worth remembering

In the separable case, support vectors lie exactly on π₊ or π₋. Once some tolerance for error is allowed (Soft Margin, below), the definition broadens: any point on the margin boundary, inside the margin, or misclassified counts too — all of them pull on where the boundary ends up.

If π₊: wᵀx+b = 40 and π₋: wᵀx+b = −50, what is the margin?
  • 10 / ‖w‖
  • 40 / ‖w‖
  • 50 / ‖w‖
  • 90 / ‖w‖
Why: margin = (c₊ − c₋)/‖w‖ = (40 − (−50))/‖w‖ = 90/‖w‖.

03Hard Margin SVM

The simplest version of SVM assumes the data is perfectly separable: some hyperplane exists with zero training points on the wrong side.

maximize  2/‖w‖    subject to   yᵢ(wᵀxᵢ + b) ≥ 1  for every point i

In words: find the boundary with the widest possible margin, under the hard constraint that every single point sits correctly on its own side, with no exceptions.

Why this fails on real data

Real data is almost never perfectly separable. A single mislabeled text, or one unusual-but-genuine text that happens to use scam-like words, and Hard Margin SVM has no valid solution at all. It offers no way to say "mostly separate this, and tolerate a few exceptions."

What do we mean by a "hard margin"?
  • The SVM allows no error in classification
  • The SVM allows some error in classification
  • The SVM allows a high amount of error in classification
Why: Hard Margin SVM requires every training point to be correctly classified, with zero tolerance for exceptions — an unbending constraint.

04Soft Margin SVM

The fix: allow some points to violate the margin — or even end up misclassified — but penalize how much they violate it.

For each point i, introduce a slack variable ζᵢ ≥ 0 that measures exactly how much that point breaks the rules:

yᵢ(wᵀxᵢ + b) ≥ 1 − ζᵢ,   ζᵢ ≥ 0

Two goals now pull in different directions: maximize the margin while also minimizing total error, combined using a hyperparameter C that weighs the error term:

min  ½‖w‖² + C·Σᵢζᵢ    subject to   yᵢ(wᵀxᵢ + b) ≥ 1 − ζᵢ,   ζᵢ ≥ 0

This is exactly what scikit-learn's SVC solves under the hood.

05What a Slack Variable Actually Means

The quantity yᵢ(wᵀxᵢ+b) is the point's functional margin — a raw score, not a geometric distance.

By construction, a point sitting exactly on π₊ or π₋ has a functional margin of exactly 1. The decision boundary itself sits at functional margin 0, which gives ζᵢ = 1. So ζᵢ is measured in half-margin-widths: ζᵢ = 1 only reaches the decision boundary, not all the way across the full margin.

ζᵢ = max(0, 1 − functional margin ᵢ)

06The Hyperparameter C

C controls exactly how much SVM is willing to trade margin width for training accuracy.

Measured directly in class on PulseTel-style data: C=0.001 → 50 support vectors; C=1 → 3; C=1000 → 3. As C shrinks, more points become "close enough" to matter, and the margin widens.

  • The penalty for any slack becomes severe.
  • The optimizer strongly prioritizes classifying every training point correctly.
  • It accepts whatever margin width that requires — even a narrow one.
  • Pushes Soft Margin SVM to behave almost like Hard Margin SVM. Risk: overfitting.
  • Slack is cheap.
  • The optimizer happily accepts some misclassified or margin-violating points.
  • In exchange, it gets a much wider, more generous margin.
  • Risk: underfitting.
Direction check

This is the same shape of tradeoff seen with α in Naive Bayes and k in kNN — a knob with an overfitting end and an underfitting end — but the direction is reversed. For α and k, larger values pushed toward underfitting. For C, larger pushes toward overfitting, smaller toward underfitting.

What happens when you use a very large value of C?
  • The model will still try to classify the training data correctly, at the cost of a narrower margin
  • The model will refuse to classify the training data correctly, regardless of C
  • Can't say for sure
Why: A large C makes any slack extremely costly, so the optimizer strongly prefers correctly classifying every training point it can, even sacrificing margin width. Large C pushes toward overfitting — the same underfitting/overfitting shape seen with α and k.

07Hinge Loss vs. Log Loss

SVM and Logistic Regression are both linear classifiers, but they penalize mistakes very differently.

Log loss (Logistic Regression) penalizes every single point continuously, even ones already correctly and confidently classified; the loss only approaches zero, never quite reaching it. Hinge loss (SVM) is max(0, 1 − y·f(x)): zero loss for any point correctly classified beyond the margin. Only points inside the margin, or on the wrong side entirely, contribute any loss at all.

Hinge Loss vs. Log Loss

Past y·f(x) = 1 (the margin boundary), hinge loss flattens to exactly zero. Log loss keeps decreasing forever, never reaching zero — every training point, however confidently classified, still nudges the Logistic Regression boundary slightly.

Why this matters

This is precisely why SVM only depends on its support vectors. Any point with zero hinge loss contributes nothing to the optimization, so it genuinely doesn't matter where it sits — only the handful of points near the boundary do. Logistic Regression has no such free pass: every point always matters, at least a little.

08Building PulseTel's SMS Filter

From formulas to a real, trained model on PulseTel's SMS dataset.

A scaling subtlety

Unlike Naive Bayes, SVM computes distances between points — it optimizes based on margin width in feature space — so feature scaling genuinely matters here. But CountVectorizer produces a sparse matrix, and standard scaling normally centers each feature around a mean of zero, turning convenient zeros into small non-zero numbers and destroying sparsity. Setting with_mean=False scales by standard deviation only, without centering, keeping the matrix sparse.

Class imbalance

PulseTel's SMS data is imbalanced — far more genuine texts than scam ones: 86.6% genuine, 13.4% scam. With far more genuine texts, an unweighted SVM can sacrifice a few scam texts to keep a wider, cleaner margin around the larger genuine-text cluster, since that costs less total slack overall. class_weight counters this by making a minority-class (scam) violation cost more in the objective.

Weighted vs. Unweighted SVM — F1 Score

On this particular split both models land at F1 = 0.8909 — still useful direct evidence to check the class_weight claim against, run and verified rather than only asserted.

A subtlety: class_weight combines with C

class_weight={0: 0.1, 1: 0.5} doesn't set a flat 5:1 ratio — it rescales the effective penalty for both classes relative to the base C being searched. A class-0 (genuine) violation costs 0.1×C, a class-1 (scam) violation costs 0.5×C: both discounted relative to an unweighted C, by different amounts, so scam violations end up penalized 5× more heavily than genuine ones — but neither class is penalized at the literal C value the search reports.

Final held-out test F1 with the best C: 0.8909.

Will SVM be impacted by an imbalance in the number of datapoints belonging to each class?
  • True
  • False
Why: With far more of one class, the optimizer can minimize total slack by favouring the majority class's margin, effectively under-penalizing mistakes on the minority class. class_weight (or resampling, e.g. SMOTE) is the standard fix, giving minority-class errors a heavier penalty in the objective.

09Recap

Generalization-first

SVM picks the boundary with the widest margin among every boundary that separates the classes, not just any boundary that happens to fit.

Margin & support vectors

The margin is the distance between π₊ and π₋. Support vectors are the points that actually determine the boundary; once slack is allowed, this includes points inside the margin or misclassified.

Hard Margin

Requires perfect separability with zero tolerance for error — which almost never holds on real data.

Soft Margin

Introduces slack variables ζᵢ ≥ 0, penalized in the objective: min ½‖w‖² + C·Σζᵢ.

The C tradeoff

Large C pushes toward Hard Margin behaviour (overfitting risk); small C allows a wider margin at the cost of more tolerated error (underfitting risk) — the reverse direction from α or k.

Hinge vs. log loss

Hinge loss hits exactly zero for confidently correct points, which is why only support vectors matter. Log loss never reaches zero — every point always has some influence.

Scaling & imbalance

SVM needs feature scaling, unlike Naive Bayes, since it works in terms of distances. Imbalanced data affects it too — fixable with class_weight or resampling.
